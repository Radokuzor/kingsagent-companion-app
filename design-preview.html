Why this is the whole product The alarm is registered inside the device at the moment the instruction arrives. FCM is best effort: Doze delays it, airplane mode drops it. So the design is never "server pushes, phone rings", it is "agent decides, phone owns the alarm". That is the one thing KingsChat can never give you, which is why the app exists at all.

Arm
Why paste, not push, for today Zero backend, zero OAuth, zero FCM. It proves the hard part (does an alarm ring on time, offline, with the phone locked) inside your two hours. Same id twice arms once, so a duplicate DM cannot double-book. There is already an optional feed URL the app can poll every 60 seconds for when you want the paste step gone.

The instruction envelope, which is the only contract between agent and app

{
  "instructions": [
    {
      "id": "rem_20260922_1400",        // same id twice = armed once (idempotent)
      "type": "reminder",                // reminder | task | command
      "title": "Workout",
      "body": "Legs day. 45 minutes.",
      "at": "2026-09-22T14:00:00+01:00", // ISO 8601 WITH offset. +01:00 is Lagos.
      "repeat": "weekdays",              // none | daily | weekdays | weekly
      "data": { "from": "kingschat" }    // free-form, passed to the notification
    }
  ]
}

What happens, end to end

You tell the agent on KingsChat
"remind me to work out at 2pm weekdays"
→
Agent writes the JSON
and DMs it to you
→
You paste into Arm
the app validates it
→
Local alarm armed
on the device
→
2:00 PM, phone locked,
airplane mode: it rings

Two of those five steps exist today and are typechecked and bundled for Android. Steps 4 and 5 need your phone. Step 2 is about thirty minutes of my work if you want it.

The one route that cannot work on this Mac

No working JDK, no Android Studio, no Android SDK. So a local Gradle build is impossible, and so is npm run android. The working routes are Expo Go on the phone over Wi-Fi (no toolchain, running in about 20 minutes) and eas build -p android for a real installable APK in the cloud later.
